# 박스야, 도망쳐! — 2주차 커밋 계획 (w2PRD)

> `week1_2` 브랜치에 실제로 올릴 커밋을 순서대로 정리한 문서입니다. 1주차 기간 안에 2주차 내용을 먼저 진행해서 브랜치 이름이 PREPRD §3의 `week2`와 다릅니다.
> 동작·수치의 원본은 [`2주차_PREPRD.md`](2주차_PREPRD.md)이고, 이 문서는 **무엇을 어떤 순서로 커밋할지**를 다룹니다. `§6.4`는 PREPRD의 6.4장을 뜻합니다.

- 기간: 11/11 ~ 11/17
- 목표: 건물 타일로 만든 3층 테스트 맵에서 발디딤으로 지붕까지 오르고, 떨어지면 높이만큼 멈추고, 가속 지붕에서 멀리 뛰기
- 범위 밖: 경비원·방해 요소·피격, 테이프 층별 배치, 해·시계·점수, 맵 끝 처리, 진짜 타일 그림 (PREPRD §2)

## 2. PREPRD와 다르게 잡은 부분

### PREPRD 이후 바뀐 1주차 동작에 맞춘 것

PREPRD를 쓴 뒤 점프 그림과 몸통박치기가 바뀌어서, 아래 내용은 PREPRD 문장 대신 이 표를 따릅니다.

| PREPRD | 이 문서 | 이유 |
|---|---|---|
| §6.2 공중에 뜨면 하강 그림 jump 3~4 | 첫 프레임만 jump 3, 그다음 착지까지 jump 4 | 지금 점프 그림은 상승 1→2, 정점 3→4, 하강 4 유지. `vy = 0`에서 시작하므로 정점 끝부터 재생됨 |
| §6.2 Slam은 돌진을 끝까지 하고, 끝난 다음 프레임 발밑 검사에서 공중에 뜰 수 있음 | 돌진 후 **출발 위치로 돌아와** 발밑 검사 | 몸통박치기가 출발 위치로 돌아오게 바뀜. 보스 맵 전용이고 보스 맵에는 발판이 없어서, 돌진으로 떨어지는 경우는 다루지 않음 |
| `Slam` 공격 판정 | 돌진 중에만 있고, 맞으면 그 자리에서 바로 복귀 시작 | 현재 코드 그대로 유지 |

### 코드와 수치에 맞춘 것

| PREPRD | 이 문서 | 이유 |
|---|---|---|
| §6.6 "차지 감속 없음은 `charge_speed()`에 이미 있음" | `charge_speed()`를 C28에서 수정 | 지금 코드는 가속 지붕에서 `WALK_SPEED`(310)를 돌려줘서 점프 시작 속도가 465가 되지 않음. 그대로 두면 gap을 못 건넘 |
| §5.3 `tiles.py`에 `TILE_W`, `ROAD_Y` 등을 정의 | `config.py`에서 가져옴 | §7과 공통 규칙(수치는 config)에 맞춤 |
| §7 `LAYER_FLOORS` | `FLOOR_YS` | `game_world.LAYER_*`(그리기 레이어)와 헷갈림 |
| §6.8 F1 발판 선 | 평평한 발판도 경사도 `draw_line`으로 그림 | `draw_rectangle`로는 경사를 못 그림. pico2d에 `draw_line(x1, y1, x2, y2, r, g, b)`가 있음 |

### 진행 순서를 바꾼 것

| PREPRD §9 | 이 문서 | 이유 |
|---|---|---|
| 5단계에서 타일 정의 | 타일 **데이터**는 C12(3단계), **그림**은 M5 | 발판·추락을 확인하려면 층이 필요함. 그림이 없는 동안은 F1 발판 선으로 확인 |
| 4단계에서 1/2/3 키, 5단계에서 N 키 | 둘 다 3단계 (C15, C17) | 걸어서 벗어나기·착지를 확인하려면 위층으로 옮길 수단이 먼저 필요함 |
| 각 설정값을 §7에서 한꺼번에 추가 | 처음 쓰는 커밋에서 추가 | 커밋마다 쓰지 않는 값이 생기지 않음 |

### 결정한 것 (PREPRD에 정해지지 않았던 항목)

| # | 질문 | 결정 |
|---|---|---|
| Q1 | 상태 머신 이벤트 형식은? (§9) | `('AIR', None)` 발밑 없음, `('FALL', None)` 시작 층 아래로, 착지는 1주차처럼 `('DONE', None)` |
| Q2 | 걸어서 발판을 벗어날 때 가로 속도는? | 그때의 이동 속도 유지 (걷기 310, 가속 465, 차지 124). 땅 위 상태에서도 `box.vx`를 현재 속도로 기록하고, Idle·Get·Slam·Recover에 들어갈 때 0으로 둠 |
| Q3 | 한 프레임에 착지와 추락이 함께 걸리면? | **착지를 먼저 검사.** 지붕에서 뛰어 지붕에 내릴 때 570을 지나는 순간 Fall이 되지 않게 함 |
| Q4 | 경사 발판에서 "이전 프레임 발 y ≥ 윗면"의 윗면은 어디서 재나? | 이전 발 y는 **이전 x의 윗면**, 이번 발 y는 **이번 x의 윗면**과 비교. 같은 x로만 비교하면 공중에서 오르막 쪽으로 움직일 때 경사를 뚫을 수 있음 |
| Q5 | 1/2/3 키를 어느 상태에서 눌러도 되나? | 어느 상태든 강제로 Jump(공중 시작). `vx = 0`, `vy = 0` |
| Q6 | N 키의 "다음 타일 시작 위치"는? | `MAP_LEFT + TILE_W·(현재 타일 + 1)`, 도로 위, Walk 또는 Idle로 시작. 마지막 타일이면 움직이지 않음 |
| Q7 | 도는 별은 어떻게 지우나? | `DizzyFx`가 `update`에서 박스가 Recover가 아니면 스스로 지움. 디버그 키는 `exit` 없이 상태를 바꾸므로 `Recover.exit`에 맡기지 않음 |
| Q8 | 테스트 맵 발판 위에서 몸통박치기하면? | 몸통박치기는 보스 맵 전용이고 보스 맵에는 발판이 없으므로 따로 처리하지 않음. B키로 구간을 바꿔 테스트 맵에서 쓸 때만 생기는 일이며, 돌진·복귀 중 `y`는 고정 (§6.2 발밑 검사 안 함) |

## 3. 파일 구조

```
project/
├─ camera.py      # 새로, C05: 모듈 변수 x, follow, reset, to_screen, visible
├─ tiles.py       # 새로, C09: TILES, Platform, draw_tile
├─ map_data.py    # 새로, C09: TEST_MAP
├─ level.py       # 새로, C09: Level (발판 목록, 그리기, 착지·발밑 찾기)
├─ box.py         # 수정: Fall·Recover·DizzyFx, 발판 착지, 가속, 월드 좌표
├─ hud.py         # 수정: Background 분리, 테두리 덮개
├─ game_world.py  # 수정: 레이어 6개, F1 카메라 반영
├─ play_mode.py   # 수정: 레벨·카메라, 디버그 키
├─ tape.py, dummy.py   # 수정: 그릴 때 카메라 반영
├─ state_machine.py    # 수정: 이벤트 형식 주석
├─ config.py      # 수정: 설정값 추가, GROUND_Y → ROAD_Y
└─ ground.py      # C10에서 삭제
```

- `camera`는 `game_framework.frame_time`처럼 **모듈 변수**로 둡니다. 그리는 객체마다 생성자로 넘기지 않아도 되고, `camera.py`는 `config`만 가져오므로 순환 import가 없습니다.
- `level`은 1주차 규칙대로 `Box(hud, level)` 생성자로 넘깁니다.

**그리기 레이어** (아래부터): `0` BG 배경 → `1` MAP 맵 → `2` ITEM 테이프·허수아비 → `3` BOX 박스 → `4` FX 줍기 연출·도는 별 → `5` UI 테두리 덮개·생명 칸·글씨

**상태 전환** (1주차 규칙에 추가되는 것)

| 상태 | 추가 규칙 |
|---|---|
| Idle, Walk, Charge | `AIR` → Jump |
| Jump | `FALL` → Fall |
| Fall | `DONE`(착지) → Recover |
| Recover | `DONE`(시간 끝) → Walk 또는 Idle |

**Box.update 순서**: 쿨타임 감소 → 상태 `do` (이동·착지·추락) → Idle·Walk·Charge·Get이면 발밑 검사

#### C16 `[week1_2] 발밑 검사와 걸어서 벗어나기` [채움] — §6.2

- `box.vx` 기록 (Q2): Walk·Charge의 `do`에서 현재 속도로, Idle·Get·Slam·Recover 진입 시 0
- 확인: 지붕 끝을 걸어 나가면 떨어지며 가로 속도가 유지됨. 차지 중 벗어나면 차지가 취소됨. 창틀 사이(60)는 걸어서 못 건넘. 아래로 내려가는 키는 없음

#### C26 `[week1_2] 가속 지붕 그리기` [채움] — §5.5
- `ph_accel`을 `composite_draw`로 기울임: 각도 = `atan2(y1 - y0, x1 - x0)`, 길이 = 선분 길이, 윗면이 선에 맞도록 가운데를 두께의 절반만큼 수직으로 내림
- 확인: 경사 막대가 F1 주황 선과 맞고, 걸으면 발이 경사를 따라감

#### C27 `[week1_2] 가속 지붕 위 걷기` [채움] — §6.6
- `ACCEL_RATE = 1.5`
- 발밑 검사에서 `on_accel_ground = (ground.kind == 'accel')`, 공중에서는 False
- `Box.walk_speed()`: 가속 지붕에서 오른쪽이면 `WALK_SPEED × ACCEL_RATE`, 그 외 `WALK_SPEED`. Walk에서 사용
- 확인: 오른쪽은 빠르고 왼쪽은 보통, 방향키를 떼면 미끄러지지 않음

#### C28 `[week1_2] 가속 지붕 차지와 점프 시작 속도` [채움] — §6.6
- `charge_speed()`: 가속 지붕이면 `walk_speed()`, 아니면 `WALK_SPEED × CHARGE_SPEED_RATE`
- `Jump.enter`에서 `vx`를 계산한 뒤에 `ground`·`on_accel_ground`를 지움
- 걸어서 벗어날 때는 C16의 `box.vx`로 465가 이어짐
- 확인: 임시 `print`로 오른쪽 차지 점프 시작 `vx` = 465, 왼쪽 310 확인 후 삭제

#### C29 `[week1_2] 공중 속도 유지` [채움] — §6.6
- `move_in_air`: 입력 방향과 `vx` 방향이 같고 `|vx| > WALK_SPEED`면 줄이지 않음. 반대 방향은 1주차처럼 `AIR_ACCEL`
- 확인: 끝에서 최대 차지 점프로 gap 지붕에 닿음. 방향키 없이 차지하고 공중에서 오른쪽을 누르면 못 닿음
