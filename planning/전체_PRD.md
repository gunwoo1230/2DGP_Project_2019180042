## 1. 게임 요약
- 게임 제목: **박스야, 도망쳐!**
- 분리수거장에서 탈출한 박스가 경비원과 환경미화원에게서 **최대한 오래 도망치는** 가로 스크롤 게임
- **하루 순환** (잡힐 때까지 끝없이 반복, 날마다 조금씩 어려워짐)

| 단계 | 시각 | 내용 | 점수 |
|---|---|---|---|
| 낮, 주택가 | 08:00 → 18:00 | 지붕·창틀·도로 3층 점프맵, 경비원 추격, 해가 왼쪽 → 오른쪽 | 진행 거리만큼 +10시간 |
| 저녁, 공원 | 18:00 고정 | 해가 오른쪽에 닿으면 경비원이 지침 → 환경미화원 보스전 | 시간 멈춤, 이기면 +4시간 |
| 밤, 주택가 | 22:00 → 08:00 | 더 어려운 점프맵, 손전등 경비원, 어두운 판, 달이 왼쪽 → 오른쪽 | 진행 거리만큼 +10시간 |
- **점수 = 도망친 시간**: 위쪽 칸에 `도망친 지 N일 N시간 N분`, 최고 기록은 파일에 저장
- 추격 중 생명 = **경비원과의 거리**, 보스전 생명 = **테이프 개수** (남은 테이프는 다음 날로 넘어감)
- 어디서 지든 처음부터 다시 시작 (0일 0시간 0분)
- 아트: 아이의 그림일기 — 크레용 스티커 그림, 인쇄된 그림일기장 모양 화면

### 조작
| 키 | 추격(점프맵) | 보스전 |
|---|---|---|
| ← / → | 이동 | 이동 |
| Space | 차지 점프 (누르는 동안 감속, 가속 지형 위에선 감속 없음) | 동일 |
| Shift | 테이프 줍기 | 몸통박치기 |

### 화면 (1600 × 900, pico2d 좌표·아래가 0)
| 영역 | x | y | 내용 |
|---|---|---|---|
| 헤더 | 20 ~ 1580 | 820 ~ 892 | 제목(박스야, 도망쳐! — 배경에 있음) / 지금(낮, 주택가) / 도망친 지(N일 N시간 N분) |
| 플레이 칸 | 20 ~ 1580 | 110 ~ 810 | 게임 화면 1560 × 700 · 하늘에 해·달 진행 길 · 왼쪽 위 테이프 생명 칸 · 오른쪽 위 거리 게이지 / 보스 체력바 |
| 원고지 칸 | 20 ~ 1580 | 22 ~ 86 | 1줄 × 24칸(한 칸 65), 팁이 일정 시간마다 바뀌며 한 칸에 한 글자씩 |
- 해·달 진행 길: 타원 중심 (800, 640), 가로 반지름 720, 세로 반지름 140 — 진행률 p일 때 x = 800 - 720·cos(πp), y = 640 + 140·sin(πp)
- 배경 이미지 `diary_frame.png` (인쇄된 실제 그림일기 모양, 1600 × 900) 위에 손글씨와 게임을 그림
- 캐릭터 0.6배 (박스 약 107 × 81) · 층 높이: 도로 y≈210, 창틀 y≈390, 지붕 y≈570 (간격 약 180) · 차지 점프 최대 약 150

## 3. 주차별 상세

각 주차 PRD는 아래 내용을 기본으로 하고, 시작 시점의 진행 상황(밀린 일, 바뀐 기획, 새로 생긴 그림)을 반영해 만듭니다.

### 1주차 (11/4 ~ 11/10) — 골격 + 박스 조작 🟨
- 기능: CORE-1~6, BOX-1~5, UI-1~3, FX-1
- 테스트 환경: 평평한 바닥(y=310), 테이프 3개, 허수아비 1개, 카메라 없음
- 완료 기준(요약): 걷기·차지 점프 높이 차이·공중 조작·테이프 줍기 연출·생명 칸·몸통박치기 1회 판정·디버그 키 동작
- 상세: `1주차_PRD.md`

### 2주차 (11/11 ~ 11/17) — 3층 맵 + 이동 규칙 ⬜
- 기능: CORE-7, MAP-1~4, BOX-6~9, FX-2
- 할 일
  - 건물 타일 구조와 변형 타일, 타일 순서 목록으로 맵 만들기
  - 위에서만 밟히는 발판 (창틀·지붕·발디딤 공통)
  - 배수관·전봇대 발디딤으로 오르기, 창틀 높이에서 옆으로 건너가기
  - 층 끝·틈에서 추락 → 떨어진 높이만큼 멈춤 (recover + dizzy)

## 6. 주차 PRD 만드는 방법
1. 이 문서 0장·2장에서 이번 주 기능 ID와 지난주 밀린 기능(🟨·⬜로 남은 것)을 확인한다
2. 4장에서 이번 주에 필요한 그림이 준비됐는지 확인하고, 없으면 임시 표현을 정한다
3. 5장에서 이번 주에 정해야 할 수치·결정을 먼저 정한다
4. `N주차_PRD.md`를 아래 틀로 작성한다
5. 주가 끝나면 이 문서의 상태 표시를 갱신하고 7장 기록에 한 줄 남긴다

### 주차 PRD 틀
```
# 박스야, 도망쳐! — N주차 PRD (기간)
1. 배경 (게임 요약 2~3줄, 지난주까지 된 것)
2. 이번 주 목표 / 범위 안 / 범위 밖
3. 시작 전에 확인할 것 (저장소 상태, 새 리소스 위치)
4. 바뀌거나 추가되는 파일
5. 리소스 (새 그림 좌표, 임시 표현)
6. 기능 요구사항 (기능 ID별 동작·수치·그림)
7. 설정값 추가분 (config.py)
8. 완료 기준 체크리스트
9. 진행 방식 (단계·커밋 단위, 공통 작업 규칙을 따름)
10. 다음 주 연결 (참고)
```

### 모든 주차 공통 작업 규칙

주차 PRD에는 이 규칙을 다시 적지 않고, 그 주차에만 다른 점이 있으면 해당 문서에 적습니다.

#### 커밋 하나의 흐름

1. **뼈대 커밋**: 쓸 곳(호출)을 먼저 연결하고, 함수 정의는 `pass`로 비워 둔다.
2. **채움 커밋**: 빈 함수를 하나씩 채운다.
3. 커밋마다 프로그램이 오류 없이 실행되고, 주차 PRD의 `확인` 항목을 눈으로 확인한 뒤 커밋한다.

```python
# play_mode.py — 쓸 곳을 먼저 연결
def update():
    game_world.update()

# game_world.py — 정의는 비워 둠, 다음 커밋에서 채움
def update():
    pass
```

#### 빈 정의에서 주의할 점

- **반환값을 쓰는 함수**(`get_bb`, 충돌 검사, 전환 조건)는 `pass`면 `None`이 돌아와 호출하는 쪽에서 오류가 난다. 정의만 `pass`로 두고, **호출 연결은 채움 커밋에서** 한다.
- **아직 빈 상태로 들어가면 빠져나오지 못하는 경우**에는 `임시 규칙`을 두고, 채움 커밋에서 지운다.
- `print` 같은 확인용 코드는 그 커밋 안에서 지우고 올린다. 임시로 남겨야 하면 커밋 설명에 적는다.

#### 공통 약속

| 항목 | 내용 |
|---|---|
| 실행 | **저장소 루트에서** `python project/main.py` (리소스 경로가 `resource/...`이므로) |
| 커밋 메시지 | `[weekN] 설명` (예: `[week2] 카메라 뼈대 추가`) |
| 코드 위치 | `project/` |
| 수치 | 코드에 직접 쓰지 않고 `config.py`에서 가져옴 |
| 시간 | 모두 `game_framework.frame_time`(초) 기준 |
| 주석 | 한국어로 짧게 |
| 객체 공통 함수 | `update()`, `draw()`, `get_bb()`, `handle_collision(group, other)` |
