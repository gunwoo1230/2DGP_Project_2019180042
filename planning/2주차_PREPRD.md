## 5. 좌표와 맵

### 5.1 월드 좌표와 카메라
- **월드 좌표** = 맵 전체 기준 좌표. y는 화면 좌표와 같다(세로로는 움직이지 않음). x만 월드 x를 쓴다.
- 화면에 그릴 때만 `화면 x = 월드 x - camera.x`. 충돌·발판·박스 위치는 모두 월드 좌표.
- 시작할 때 `camera.x = 0` → 월드 x와 화면 x가 같다 (1주차 좌표가 그대로 맞음).
- 맵의 첫 타일 왼쪽 끝 = 월드 x `PLAY_LEFT`(20). 타일 i의 왼쪽 끝 = `20 + 600·i`.
- 카메라 따라가기 (CORE-7)
  - 박스가 화면 x `CAMERA_FOLLOW_X = 640`보다 오른쪽으로 가면 카메라가 따라감: `camera.x = max(camera.x, box.x - 640)`
  - **뒤로는 돌아가지 않음** (camera.x는 줄어들지 않음)
  - 최대값: 맵 오른쪽 끝이 화면 x 1580(`PLAY_RIGHT`)에 오는 위치에서 멈춤
- 박스 좌우 한계 (`clamp_x` 수정)
  - 왼쪽: `camera.x + PLAY_LEFT + BOX_BB_W/2` (화면 왼쪽 끝에 막힘 → 되돌아갈 수 없음)
  - 오른쪽: 맵 오른쪽 끝 - `BOX_BB_W/2` (보이지 않는 벽)
- 박스 시작 위치: 월드 x `BOX_START_X`(200), 도로 위

### 5.3 건물 타일 (MAP-1·2)
- 타일 1칸 = **폭 600**, 세로는 플레이 칸 전체(y 110 ~ 810)
- 층 높이: 도로 `ROAD_Y = 210`, 창틀 `LEDGE_Y = 390`, 지붕 `ROOF_Y = 570` (간격 180)
- 발판 = **선분** `(종류, x0, y0, x1, y1)`. 윗면이 밟히는 선이다. 평평하면 `y0 = y1`, 경사면 `y0 ≠ y1`.
- 아래 정의는 **타일 안 좌표**(x 0 ~ 600)이고, y는 화면 좌표 그대로다. 그대로 `tiles.py`에 옮겨 쓴다.

```python
TILE_W = 600
ROAD_Y, LEDGE_Y, ROOF_Y = 210, 390, 570
PEGS_Y = (270, 330, 450, 510)          # 배수관 발디딤 (390은 창틀이 대신함)


def basic_ledges():
    return [('ledge', a, LEDGE_Y, a + 120, LEDGE_Y) for a in (60, 240, 420)]


TILES = {
    # 'walls': 벽(건물 몸통) x 범위, 'deco': 밟지 않는 장식(배수관·전봇대) 사각형, 'platforms': 발판 선분
    'start': {'walls': [], 'deco': [], 'platforms': []},
    'basic': {'walls': [(40, 560)], 'deco': [],
              'platforms': [('roof', 40, ROOF_Y, 560, ROOF_Y)] + basic_ledges()},
    'pipe':  {'walls': [(40, 560)], 'deco': [('pipe', 82, ROAD_Y, 98, ROOF_Y)],
              'platforms': [('roof', 40, ROOF_Y, 560, ROOF_Y)] + basic_ledges()
                           + [('peg', 60, y, 120, y) for y in PEGS_Y]},
    'pole':  {'walls': [(200, 560)], 'deco': [('pole', 92, ROAD_Y, 108, 600)],
              'platforms': [('roof', 200, ROOF_Y, 560, ROOF_Y),
                            ('ledge', 220, LEDGE_Y, 340, LEDGE_Y), ('ledge', 420, LEDGE_Y, 540, LEDGE_Y)]
                           + [('peg', 70, y, 130, y) for y in (270, 330, 390, 450, 510)]},
    'accel': {'walls': [(40, 560)], 'deco': [],
              'platforms': [('accel', 40, 630, 560, ROOF_Y)] + basic_ledges()},
    'gap':   {'walls': [(240, 560)], 'deco': [],
              'platforms': [('roof', 240, ROOF_Y, 560, ROOF_Y),
                            ('ledge', 260, LEDGE_Y, 380, LEDGE_Y), ('ledge', 440, LEDGE_Y, 540, LEDGE_Y)]},
}
# 모든 타일 맨 아래에 도로 (끊기지 않음)
for tile in TILES.values():
    tile['platforms'].insert(0, ('road', 0, ROAD_Y, TILE_W, ROAD_Y))
```

| 타일 | 설명 | 의도 |
|---|---|---|
| start | 도로만 있는 빈터 | 시작 위치 |
| basic | 지붕 + 창틀 3개(사이 60) + 도로 | 창틀은 짧은 점프 연속, 걸어서는 못 건넘 |
| pipe | basic + 벽의 배수관 발디딤 4개 | 도로 → 270 → 330 → 창틀 390 → 450 → 510 → 지붕 570 (60 간격) |
| pole | 왼쪽 빈터에 전봇대 발디딤 5개, 건물은 x 200부터 | 390 발디딤에서 오른쪽 창틀로, 510에서 오른쪽 지붕으로 건너감 |
| accel | 지붕이 630 → 570 내리막 (가속 지붕) | 다음 지붕 높이에서 끝남 |
| gap | 건물이 x 240부터 → 앞 지붕 끝과 **280** 떨어짐 (발 폭을 빼면 실제로 날아야 하는 거리 약 240) | 보통 최대 점프(약 200)로는 못 건너고, 가속 지붕에서 뛰면 건넘(약 330) |

- 지붕 사이 기본 간격: 타일 경계 양쪽 40씩 = **80** (보통 점프로 건넘)
- 발 폭(`FOOT_HALF` 20) 때문에 발판 끝에서 박스 가운데가 20px 더 나가도 서 있을 수 있다 → 실제로 날아야 하는 거리 = 간격 - 40
- 수치 근거: 최대 점프 체공 약 0.71초. 차지 감속 뒤 보통 점프 가로 거리 약 200, 가속(465 px/s) 점프 약 330

## 6. 기능 요구사항

### 6.1 발판과 착지 (BOX-6)
- 발판 `Platform(kind, x0, y0, x1, y1)` (월드 좌표)
  - `surface_y(x)`: x에서의 윗면 높이 (x0~x1 사이 직선 보간)
  - `covers(x)`: 박스 **발 폭**(x ± `FOOT_HALF = 20`)이 발판 x 범위와 겹치면 True. 경사면 높이는 박스 x를 x0~x1 안으로 잘라 계산
- **위에서만 밟힘**: 도로를 포함한 모든 발판은 아래에서 위로 통과한다. 내려오는 중(`vy <= 0`)에 **이전 프레임 발 y ≥ 윗면 > 이번 프레임 발 y**일 때만 착지
  - 여러 발판이 걸리면 가장 높은 윗면에 착지
  - 착지하면 `y = 윗면`, `vy = 0`, 서 있는 발판 `box.ground = 그 발판`
- 1주차의 `y <= GROUND_Y` 착지는 이 방식으로 바뀐다. 도로도 발판이므로 도로 아래로 떨어지는 일은 없다.

### 6.2 발밑 검사 (BOX-7)
- 땅 위 상태(Idle, Walk, Charge, Get, Slam이 끝난 뒤)에서 매 프레임 발밑을 검사
  - 지금 x에서 `covers`이고 `|윗면 - y| ≤ SNAP = 8`인 발판이 있으면 그 위에 붙음: `y = 윗면` (경사면을 걸으면 y가 따라감)
  - 없으면 공중에 뜸 → 아래 `('AIR', None)` 처리
- 몸통박치기(Slam) 중에는 발밑 검사를 하지 않고 돌진을 끝까지 한다. 끝난 다음 프레임 발밑 검사에서 발판이 없으면 공중에 뜸
- 발밑에 발판이 없으면 `('AIR', None)` 이벤트 → **Jump 상태로 들어가되 위로 뛰지 않음**(`vy = 0`, 하강 그림 jump 3~4). 추락인지 아닌지는 6.3 규칙이 정한다
- 차지 중 걸어서 끝을 벗어나면 차지는 취소되고 같은 처리
- **스스로 내려가는 키는 없다.** 아래층으로 가는 방법은 걸어서 끝을 벗어나거나 틈에 빠지는 것뿐

### 6.3 추락 (BOX-7) — 시작 층 기준
- **층 구간** (아래 경계 = 그 층의 최소 높이)

| 층 | 높이 구간 | 최소 높이 |
|---|---|---|
| 도로 | 210 ≤ y < 390 | 210 |
| 창틀 | 390 ≤ y < 570 | 390 |
| 지붕 | 570 ≤ y | 570 |
- 공중에 뜨는 순간(점프 시작, 또는 걸어서 발판을 벗어남) **출발 높이 `takeoff_y`**를 기록하고, 그 높이가 속한 층을 **시작 층**으로 정한다
  - 발디딤도 높이로 층이 정해진다: 270·330 → 도로 층, 390·450·510 → 창틀 층
  - 가속 지붕(570 ~ 630)은 지붕 층
  - 높이 계산 오차를 막기 위해 `takeoff_y + 1`로 층을 찾는다
- **Jump 중 `y < 시작 층의 최소 높이`가 되면 Fall 상태로 바뀌고 fall 그림을 재생한다**
  - 예) 지붕에서 뛰어 틈에 빠짐 → 570 아래로 내려가는 순간 추락
  - 예) 창틀에서 뛰어 창틀 사이로 빠짐 → 390 아래로 내려가는 순간 추락
  - 예) 발디딤 330에서 헛디뎌 도로로 내려옴 → 도로 층(최소 210) 안이므로 추락 아님, 그냥 착지
- 시작 층 안에서 내려와 착지하면(같은 층의 다른 발판, 더 낮은 발디딤 포함) 추락이 아니므로 멈추지 않는다
- Fall 동안
  - 중력·공중 좌우 조작은 Jump와 같음 (가로 속도 유지 규칙 6.6 포함)
  - 그림: fall 1~4를 10fps로 **한 번 재생하고 4번째 장 유지** (테이프가 점점 위로)
  - Space·Shift 무시
- 착지는 6.1 규칙. Fall에서 착지하면 `drop = takeoff_y - 착지 y`로 6.4 멈춤 시간을 정함

### 6.4 추락 멈춤 (BOX-8, FX-2)
- **Fall 상태에서 착지하면 항상 Recover 상태**, 멈춤 시간 = `drop / STUN_PX_PER_SEC(180)` 초
  - 창틀 → 도로 = 1초, 지붕 → 창틀 = 1초, 지붕 → 도로 = 2초, 발디딤 510 → 도로 ≈ 1.7초, 창틀 390 → 발디딤 330 ≈ 0.3초
- Jump 상태에서 착지하면(시작 층 안 또는 위층) 멈추지 않고 바로 Walk 또는 Idle
- Recover 동안
  - 그림: recover 3장을 7fps로 반복 (@ 눈)
  - 머리 위 도는 별: `dizzy` 2장을 6fps로 번갈아, 위치는 발 + `BOX_BODY_H` + `DIZZY_GAP(18)` 위, 배율 0.6
  - 이동·점프·Shift 무시 (좌우 눌림 기록은 계속)
  - 시간이 끝나면 `('DONE', None)` → 방향키가 눌려 있으면 Walk, 아니면 Idle

### 6.5 발디딤 오르기 (MAP-4)
- 발디딤·창틀·지붕은 모두 같은 발판 규칙(6.1)이므로 **따로 오르기 코드는 없다.** 아래에서 뛰어 통과한 뒤 내려오며 밟는다.
- 발디딤 간격 60 > 최소 점프 48 → 살짝 차지해야 다음 발디딤에 닿는다
- 한 번 점프(최대 150)로는 다음 층(180)에 닿지 않는다
- pole 타일: 390 발디딤에서 오른쪽 창틀(x 220부터)로, 510 발디딤에서 오른쪽 지붕(x 200부터)으로 뛰어 건너간다

### 6.6 가속 지붕 (BOX-9)
- 박스가 `kind == 'accel'` 발판 위에 서 있으면 `on_accel_ground = True`
- 가속 지붕 위에서 **오른쪽으로 걸을 때** 속도 = `WALK_SPEED × ACCEL_RATE(1.5)` = 465. 왼쪽으로 걸을 때는 보통 속도
  - 자동으로 미끄러지지는 않는다 (방향키를 눌러야 움직임)
- 가속 지붕 위에서는 차지 중에도 감속하지 않는다 (1주차 `charge_speed()`에 이미 있음)
- 점프 시작 가로 속도 = 그때의 이동 속도 (가속이면 465)
- **공중 속도 유지**: 공중 좌우 조작은 `dir × WALK_SPEED`로 속도를 맞추는데, 그러면 465가 310으로 깎인다. 그래서
  - 입력 방향과 지금 가로 속도의 방향이 같고, 속도 크기가 `WALK_SPEED`보다 크면 **속도를 줄이지 않는다**
  - 반대 방향을 누르면 1주차처럼 `AIR_ACCEL`로 천천히 바뀐다
  - 착지하면 다시 땅의 속도 규칙(가속 지붕이 아니면 310)
- 결과: 가속 지붕 끝에서 최대 차지 점프 → 약 330px 날아 gap 타일 지붕(280 떨어짐, 실제 약 240)에 닿는다

### 6.7 카메라 (CORE-7)
- 5.1 규칙. 박스 update 다음, 그리기 전에 카메라를 갱신
- 화면 기준으로 그리는 것: 배경, UI(생명 칸·글씨·테두리 덮개), 줍기 연출이 생명 칸으로 날아가는 도착점
  - 줍기 연출은 **출발은 월드 좌표**(테이프 위치), **도착은 화면 좌표**(생명 칸)이므로, 연출 위치를 화면 좌표로 계산해 그린다 (만들 때 테이프 화면 x로 바꿔 시작)
- 월드 기준으로 그리는 것: 맵, 테이프, 허수아비, 박스, 도는 별
- F1 충돌 박스·발판 선도 카메라를 빼서 그린다

### 6.8 디버그 키
| 키 | 동작 |
|---|---|
| F1 | 충돌 박스 + **발판 윗면 선**(빨강, 가속 지붕은 주황) 보기 / 끄기 |
| B | 구간 전환 (1주차 그대로) |
| R | 리셋: 박스를 시작 위치로, 카메라 0, 생명·테이프·허수아비 처음으로 |
| N | 다음 타일 시작 위치(도로 위)로 박스 이동, 카메라도 따라감 (테스트용 건너뛰기) |
| 1 / 2 / 3 | 지금 x에서 도로 / 창틀 / 지붕 높이 + 1px로 박스를 옮겨 공중 상태로 떨어뜨림 (추락 시험용, 출발 높이 = 옮긴 높이 → 아래에 발판이 없으면 바로 추락) |
| ESC | 종료 |

### 6.9 1주차 기능과의 관계
- 테이프 3개(월드 x 500, 900, 1300)와 허수아비(월드 x 1200)는 도로 위 그대로. 카메라가 움직이면 함께 화면 밖으로 지나간다.
- 줍기(Get)·몸통박치기(Slam)는 땅 위 어느 발판에서도 된다. 테이프는 도로에만 있으므로 이번 주엔 도로에서만 확인
- 리셋(R)은 카메라와 박스 높이까지 처음으로

## 9. 진행 방식
- 공통 작업 규칙(전체 PRD 6장)을 따른다. 먼저 `planning/w2PRD.md`에 커밋 계획을 쓰고 진행한다.
- 추천 단계 (각 단계가 끝날 때마다 실행해서 확인 가능한 상태)
  1. 레이어 정리: HUD를 배경·UI로 나눔, 테두리 덮개
  2. 카메라·월드 좌표: 긴 도로(타일 `start`만 여러 개)에서 1주차 기능 확인
  3. 발판 시스템: 발판 선분, 위에서만 밟힘, 발밑 검사, F1 발판 선
  4. 추락·멈춤: 시작 층 판정, Fall·Recover 상태, 도는 별, 1/2/3 키
  5. 건물 타일·테스트 맵: 타일 5종 정의와 임시 그림, N 키
  6. 가속 지붕: 경사면, 가속, 공중 속도 유지
  7. 정리·프레임 독립 확인
- 상태 머신 이벤트 추가: `('AIR', None)`(발밑 없음 → Jump), `('FALL', None)`(시작 층 아래로 → Fall), 착지 이벤트 — 형식은 w2PRD에서 정한다
- 단계 3~4는 서로 맞물리므로, 추락 판정(Fall)을 먼저 만들고 멈춤(Recover)을 나중에 채운다
