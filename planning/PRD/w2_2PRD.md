# 박스야, 도망쳐! — 2주차_2 커밋 계획 (w2_2PRD)

> `week2_2` 브랜치에 실제로 올릴 커밋을 순서대로 정리한 문서입니다.
> 동작·수치의 원본은 [`w2_2PREPRD.md`](w2_2PREPRD.md) (11/16 수정판, 비둘기 = 앉았다가 낮게 돌진)이고, 이 문서는 **무엇을 어떤 순서로 커밋할지**를 다룹니다. `§7.2`는 PREPRD의 7.2장을 뜻합니다.

- 작업 시점: 11/16 ~
- 목표: 같은 시드로 방해 요소(살아 있는 창문·물웅덩이)와 테이프 자리를 규칙으로 정하고, 비둘기는 평평한 지붕에 있는 시간으로 등장시킨다 (앞쪽 지붕에 앉아 "!" → 낮게 돌진, 점프로 넘어 피함). 창문·비둘기에 맞으면 도로까지 떨어져 기절하고, 물웅덩이는 느려지게 한다. 생명 칸이 꽉 찼을 때 Shift를 누르면 "가득 참!"을 보여 준다
- 그대로인 것: 낮 맵 조각·타일·창문·빨랫줄 만들기(w2_1), 점수·해·낮 끝, 경비원, 보스 무대 (PREPRD §1)
- 범위 밖: 진짜 그림(창문 불 켜짐·열림, 물웅덩이, 비둘기, 느낌표), 날마다 난이도 올리기, 밤 맵, 소리, 물 튀김 효과, Tiled (PREPRD §1, §2)

## 1. 작업 규칙

[전체 PRD 6장의 공통 작업 규칙](00_전체PRD.md#모든-주차-공통-작업-규칙)을 따릅니다. 이 주차에만 다른 점은 아래와 같습니다.

- 커밋 메시지 접두어는 `[week2_2]`입니다.
- 커밋마다 프로그램이 오류 없이 도는지 봅니다. 각 `확인` 항목은 **M 단계가 끝날 때마다** 키 입력을 넣는 스크립트로 한꺼번에 확인합니다. 스크립트는 저장소 밖에 둡니다.
- 배치 규칙은 참고 구현 `planning/preview/w2_2_gen_reference.py`와 **결과를 비교하는 스크립트**로 확인합니다. 시드 여러 개로 살아 있는 창문, 물웅덩이 x, 테이프 자리가 같은지 봅니다. 참고 구현은 타일 왼쪽 끝이 `i × 600`이라 게임 x에서 `MAP_LEFT`(20)를 빼고 비교합니다. 이 스크립트도 저장소 밖에 둡니다.
- 피격 동작(C04 ~ C06)은 방해 요소보다 먼저 만듭니다. 그래서 확인 스크립트에서 `box.hit()`을 직접 불러 확인합니다. 게임에는 피격 디버그 키를 두지 않습니다.
- 마지막(C14)에는 w1_4·w2_1 검사를 다시 돌립니다. 방해 요소가 끼어들지 않게 `H`로 끄고 돌리고, 바닥 고정 테이프(`TAPE_XS`)를 쓰던 검사는 바꾼 내용을 기록합니다.
- 푸시는 마지막에 요청이 있을 때 합니다.

## 2. PREPRD와 다르게 잡은 부분, 결정한 것

### 결정한 것 (PREPRD에 정해지지 않았던 항목)

| # | 질문 | 결정 |
|---|---|---|
| Q1 | 조각 범위는 어떻게 넘기나? | `make_day_map(rng)`이 `(names, chunks)`를 돌려줌 (난수 쓰는 양은 그대로). `map_data.test_chunks(names)`는 1번부터 3칸씩 묶음 (참고 구현 `test_chunks`). `new_map`은 `(names, chunks, rng)`, `Level.load(names, chunks, rng)`. 보스 무대는 `chunks = []`, `rng = None`이라 배치하지 않음 |
| Q2 | 배치 결과는 어디에 두나? | `Level.load`에서 `make_lines` 다음에 `place_hazards(rng)` → `place_tapes(rng)` 순서로 부름 (PREPRD §5.1). 결과는 `level.hazards`(타일 번호마다 `None` / `('window', 창문 번호)` / `('puddle', 타일 안 x)`)와 `level.tapes`(`(월드 x, 발 높이 y)` 목록). 게임 객체는 `play_mode`가 이 목록으로 만듦 (Q6) |
| Q3 | 참고 구현과 난수 순서를 맞추려면? | 참고 구현 그대로: ① 타일 1·2번(`i <= HAZARD_FREE`)과 `start`에서는 `rng.random()`을 **부르지 않음** ② 종류 고르기는 후보가 하나여도 `rng.choice` ③ 바로 앞 타일에 방해 요소가 없으면 앞 종류는 `None`으로 ④ 테이프 층 고르기는 후보 층이 하나여도 `rng.choices` ⑤ `rng.uniform`은 지붕일 때만. 하나라도 다르면 그 뒤 결과가 모두 달라짐 |
| Q4 | 오르는 곳 x 범위(`CLIMB_X`)는 어디서? | `tiles.climb_x(name)`이 타일 정의에서 계산: `pipe`는 `(벽 왼쪽 - PIPE_PEG_W, 벽 왼쪽)` = (-20, 40), `pole`은 `POLE_PEG_X` = (70, 130). 참고 구현의 숫자와 같고, 배수관 위치가 바뀌면 같이 따라감 |
| Q5 | 테이프 자리 후보 순서 | 참고 구현 `place_tapes`와 같게: 조각의 타일을 왼쪽부터 (지붕·가속 지붕 발판 → 살아 있지 않은 창틀), 그다음 빨랫줄 전체에서 왼쪽 끝이 이 조각 타일에 있는 것 (`level.tile_index(line.x0)`). 지붕 후보는 `tile['platforms']` 순서(도로 → 지붕 → 창틀 → 받침)에서 `roof`·`accel`만 |
| Q6 | 객체는 어느 레이어에? | `Puddle`, `LiveWindow`, `PigeonSpawner`, `Pigeon`은 `LAYER_ITEM`이라 다시 시작할 때·보스 구간으로 갈 때 테이프와 함께 지워짐 (비둘기는 지붕 높이로 날아서 박스 아래 레이어여도 됨). "!"는 따로 객체를 두지 않고 `Pigeon`이 앉아 있는 동안 자기 머리 위에 그림. 박스를 따라다니는 `FullFx`("가득 참!")만 `LAYER_FX`에 두고 스스로 지움 |
| Q7 | 충돌 그룹 | `'box:puddle'`, `'box:window'`, `'box:pigeon'`. 박스 쪽 처리는 `Box.handle_collision`에서 함. 창문은 `open`일 때만, 비둘기는 돌진하는 동안만 `box.hit()`를 부름. `get_bb`는 F1에 그리려고 항상 범위를 돌려줌 |
| Q8 | `H` 켜기/끄기 상태는? | `hazard.enabled` (모듈 변수). `G`의 `guard.enabled`처럼 다시 시작해도 유지됨. 끄면 웅덩이 감속 없음, 창문이 `lit`에서 안 넘어감, 비둘기 시간이 안 쌓임, `box.hit()`도 무시. 그림은 그대로 보임 |
| Q9 | 피격 조건은 어디서 보나? | `box.hit()` 한 곳에서: `zone == 'chase'`, `hazard.enabled`, 상태가 `Hit`·`Recover`·`Caught`가 아님, 무적 아님. 방해 요소 쪽은 `day.phase == 'chase'`일 때만 움직임 (낮 끝·잡힘 중에는 안 열리고 안 옴) |
| Q10 | `Hit`으로는 어떻게 들어가나? | `catch()`처럼 `state_machine.reset(Hit)`. `Get`(줍기) 중이면 그대로 끊김 (테이프는 `Get.enter`에서 이미 연출로 넘어감, PREPRD §8). `Charge`는 차지가 버려짐 |
| Q11 | `Hit` 공중 이동 | `move_in_air(control=True, kinds=None)`로 바꾸고 `find_landing(..., kinds=None)`에 착지할 발판 종류를 넘김. `Jump`·`Fall`은 그대로, `Hit`은 `control=False, kinds=('road',)`. 그래서 좌우 키 입력도, 도로 아닌 발판 착지도 없음 |
| Q12 | 착지 뒤 기절과 무적 | `Hit`에서 도로에 닿으면 `('DONE', None)` → `Recover` (기절 시간 계산은 그대로, 출발 높이 = 맞은 순간 y). `Hit.enter`가 `box.from_hit = True`를 켜 두고, `Recover.exit`에서 켜져 있으면 `box.invincible = HIT_INVINCIBLE`로 두고 끔. 무적은 `Box.update`에서 줄고, 그동안 `HIT_BLINK = 0.1`초마다 박스를 숨김 (새 수치) |
| Q13 | 물웅덩이 판정 | `Puddle.get_bb` = 웅덩이 사각형 (도로 윗면 210에서 위로 6, 아래로 12). 충돌이 나면 `Box.handle_collision`이 **땅 위 상태이고 `ground.kind == 'road'`이고 발(x ± `FOOT_HALF`)이 웅덩이 x와 겹칠 때만** `box.in_puddle = True`. 테이프(`near_tape`)처럼 다음 `update`에서 씀. 느림은 `floor_speed()`에 곱해서 걷기·차지가 같이 느려짐. 공중 목표 속도(`air_speed`)는 `FLOOR_SPEEDS`를 그대로 써서 안 바뀜. 웅덩이에서 뛰면 시작 가로 속도는 차지 속도라 느리게 출발하고, 공중에서 원래 속도로 돌아옴 |
| Q14 | 웅덩이 들어가는 순간 그림 | `in_puddle`이 꺼져 있다가 켜지는 순간 `puddle_flash = PUDDLE_FLASH`. `Walk.draw`가 그동안 `jump` 대신 `hit` 그림 (깡충 없음). 다른 상태는 그대로 |
| Q15 | 창문이 박스가 섰는지 아는 법 | `LiveWindow`는 박스와 창틀 월드 좌표(`x`, `y`)를 들고, `box.ground`가 `kind == 'ledge'`이고 `x0 == x`이며 박스가 땅 위 상태일 때 `shake`를 시작함. `shake`가 시작되면 박스가 떠나도 `open`까지 진행함 (0.3초 안에 벗어나면 안 맞음, PREPRD §12.2) |
| Q16 | 비둘기 시간을 재는 조건 | 땅 위 상태(`Idle`·`Walk`·`Charge`·`Get`)이고 `box.ground.kind == 'roof'`일 때만 쌓음. 570 못(`peg`)·가속 지붕·빨랫줄은 안 쌓임. 박스가 있는 타일 번호가 `HAZARD_FREE` 이하면 쌓지 않음. **공격 중(앉기 → 화면 왼쪽 밖으로 사라질 때까지)에는 쌓지 않음** (한 번에 하나). 쌓는 시간 `PIGEON_CHECK_TIME = (4, 8)`은 `random.uniform`으로 매번 새로 |
| Q17 | 비둘기 앉는 자리와 높이 | x = `min(박스 x + PIGEON_SIT_DX, 카메라 왼쪽 + SCREEN_W - 60)` (화면 오른쪽 끝 - 60을 월드 좌표로). 높이는 박스가 선 지붕과 상관없이 `ROOF_Y` 기준: 앉기 = 그림 아래 끝이 570 (가운데 595), 돌진 = 가운데 `570 + PIGEON_FLY_H` = 605 (위 끝 630). 그 자리 아래에 `roof`·`accel` 발판이 있는지(`level.find_ground(x, ROOF_Y)`)는 `perched`로만 들고 있음. 임시 그림은 같아서 진짜 앉기 / 날갯짓 그림이 오면 씀 |
| Q18 | 비둘기 상태와 충돌 박스 | `sit`(`PIGEON_ALERT_TIME` 동안, 충돌 없음, 머리 위 `ALERT_GAP`에 "!") → `dash`(왼쪽으로 `PIGEON_SPEED`, 높이 고정, 충돌 있음) → 오른쪽 끝이 화면 왼쪽 밖(`DRAW_MARGIN` 포함)으로 나가면 스스로 지우고 `PigeonSpawner`에 알림. 충돌 박스는 PREPRD대로 그림 크기 70 × 50 그대로 |
| Q19 | "가득 참!"은 어디서? | `Box.update`에서 땅 위 상태(`Idle`·`Walk`)이고 `zone == 'chase'`이고, Shift를 눌렀거나 기억 중이고(`shift_buffer > 0`), `near_tape`가 있고, `hud.is_full()`일 때 → `FullFx`를 띄우고(이미 떠 있으면 시간만 처음부터) `hud.flash_full()`을 부르고 `shift_buffer = 0`. 끝 0.2초 흐려짐은 `FULL_FADE_TIME = 0.2` (새 수치), `opacify` |
| Q20 | `TEST_MAP`에도 배치하나? | 한다. 같은 규칙으로 3칸 조각(Q1)을 써서 `M`으로 방해 요소·테이프를 시험할 수 있음 |
